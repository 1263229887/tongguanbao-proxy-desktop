# 平台前置机跨租户对接文档

> 版本：v1.0  
> 更新时间：2026-09-20  
> 适用对象：平台 Windows 前置机开发、测试和部署人员  
> 对接范围：使用一个平台特殊 Key 处理多个业务租户的单一窗口暂存任务

## 1. 改造目标

平台前置机使用后端提供的一个平台特殊 Key，通过现有 Agent 接口处理所有有效业务租户的任务：

```text
后端跨租户下发任务
  -> 平台前置机写入统一 OutBox
  -> 平台前置机回报投递状态
  -> 单一窗口在统一 InBox 生成回执
  -> 平台前置机携带 taskId 上传回执原文
  -> 后端按任务真实 tenantId 更新数据
```

平台前置机不需要维护各业务租户的企业 Key，也不需要切换 Key。`pull`、`status`、`receipts`、`heartbeat` 四个接口始终使用同一个平台 Key。

## 2. 与普通租户前置机的差异

| 项目 | 普通租户前置机 | 平台前置机 |
|---|---|---|
| 鉴权密钥 | 一个业务租户的企业 Key | 平台特殊 Key |
| 拉取范围 | 当前租户 | 所有启用、未过期的业务租户 |
| `pull` 响应 | 原有字段 | 额外返回任务真实 `tenantId` |
| `status` | 使用当前租户上下文 | 后端按 `taskId + instanceName + dispatchToken` 定位真实任务 |
| `receipts` | `taskId` 可不传 | `taskId` 必传 |
| 回执归属 | 当前租户 | 后端校验 `taskId + ClientSeqNo` 后使用任务真实租户 |
| OutBox/InBox | 统一目录 | 仍然是统一目录，不按租户拆分 |

`tenantId` 只用于前置机账本、审计和排障，不用于选择目录，也不能由前置机用来决定后端数据归属。

## 3. 基础配置与公共协议

### 3.1 建议配置

```yaml
server:
  base-url: https://api.example.com
  agent-key: sk-platform-replace-with-real-key

instance:
  name: PLATFORM-AGENT-01

customs:
  supported-trade-modes: [export, import, "9610"]
  outbox: D:\\Deccus001\\OutBox
  inbox: D:\\Deccus001\\InBox

poll:
  task-interval: 10s
  inbox-interval: 3s
  heartbeat-interval: 30s
```

`instanceName` 必须稳定且全局可辨识，服务重启后不能随机变化。

### 3.2 HTTP 约定

| 项目 | 约定 |
|---|---|
| 接口前缀 | `/admin-api/declaration/agent` |
| 协议 | 生产环境必须使用 HTTPS |
| 方法 | 全部为 `POST` |
| 请求类型 | `Content-Type: application/json` |
| 鉴权请求头 | `X-Agent-Key: sk-...` |
| 日期时间格式 | `yyyy-MM-dd HH:mm:ss` |
| 字符编码 | UTF-8 |

不需要发送登录 Token、`tenant-id` 请求头或用户 ID。

成功响应统一为：

```json
{
  "code": 0,
  "msg": "",
  "data": {}
}
```

只有 HTTP 为 `2xx` 且响应体 `code = 0` 才表示调用成功。连接中断、超时或响应无法解析均按“结果未知”处理。

## 4. 完整处理流程

1. 定时调用 heartbeat，上报实例和目录健康状态。
2. 定时调用 pull 获取任务，将返回的全部关键字段持久化到本地投递账本。
3. 校验业务模块、租约、Base64 和 SHA-256。
4. 使用写前日志和原子 rename 将 DEC XML 写入统一 OutBox。
5. 使用 pull 返回的原始 `taskId`、`instanceName` 和 `dispatchToken` 回报状态。
6. 扫描统一 InBox，读取稳定的回执文件原始字节。
7. 使用安全 XML 解析器只提取 `ClientSeqNo`，通过投递账本找到对应的 `taskId` 和 `tenantId`。
8. 携带 `taskId` 上传未修改的回执原始字节。
9. 将后端明确响应持久化到本地回执账本；网络异常时保留原文件并重试。

## 5. 拉取任务

### 5.1 请求

```http
POST /admin-api/declaration/agent/tasks/pull
Content-Type: application/json
X-Agent-Key: sk-platform-replace-with-real-key
```

```json
{
  "instanceName": "PLATFORM-AGENT-01",
  "tradeModes": ["export", "import", "9610"],
  "batchSize": 5
}
```

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `instanceName` | 是 | 非空，最长 64 | 必须使用稳定的平台实例名。 |
| `tradeModes` | 是 | 非空数组 | 元素只能为 `export`、`import`、`9610`。 |
| `batchSize` | 否 | 1～100 | 省略时默认 5，后端当前实际封顶 20。 |

### 5.2 响应

```json
{
  "code": 0,
  "msg": "",
  "data": {
    "tasks": [
      {
        "taskId": 33,
        "tenantId": 2001,
        "orderId": 68,
        "tradeMode": "export",
        "businessModuleCode": "DECCUS001",
        "clientSeqNo": "202609181234560001",
        "fileName": "DEC报关单_EXPORT_202609181234560001.xml",
        "xmlSha256": "ab3d7f0d0cdb0000000000000000000000000000000000000000000000000000",
        "dispatchToken": "bb4635d4-0dc4-4ec8-8f33-8f9b7b650662",
        "leaseExpireAt": "2026-09-18 12:50:00",
        "decXmlBase64": "PD94bWwgdmVyc2lvbj0iMS4wIiBlbmNvZGluZz0iVVRGLTgiPz4..."
      }
    ]
  }
}
```

没有任务时 `tasks` 为空数组，这不是错误。

| 响应字段 | 说明 |
|---|---|
| `taskId` | 后端任务主键，后续状态和回执必须使用。 |
| `tenantId` | 任务真实业务租户，仅用于账本、审计和排障。 |
| `orderId` | 后端业务订单标识。 |
| `tradeMode` | 任务分类，不用于选择本地目录。 |
| `businessModuleCode` | 当前固定为 `DECCUS001`。其他值必须拒绝投递并告警。 |
| `clientSeqNo` | 后端生成的单一窗口业务流水号，不得修改或重新生成。 |
| `fileName` | 后端指定的 OutBox 目标文件名。 |
| `xmlSha256` | DEC 原始字节 SHA-256 小写十六进制值。 |
| `dispatchToken` | 本次分派令牌，状态回报必须原样带回。 |
| `leaseExpireAt` | 分派租约到期时间。 |
| `decXmlBase64` | DEC XML 原始字节的 Base64。 |

### 5.3 投递账本

每个拉取任务至少持久化：

- `taskId`
- `tenantId`
- `orderId`
- `clientSeqNo`
- `tradeMode`
- `fileName`
- `xmlSha256`
- `dispatchToken`
- `leaseExpireAt`
- 本地投递状态、实际路径、临时路径、最后错误和重试时间

建议以 `taskId + clientSeqNo + xmlSha256` 作为投递轮次唯一键。不同租户可能出现相同 `clientSeqNo`，不能只用 `clientSeqNo` 作为全局唯一键。

### 5.4 写入 OutBox

每条任务按以下顺序处理：

1. 校验 `businessModuleCode = DECCUS001`。
2. Base64 解码并复算 SHA-256；不一致时不得写盘，回报 `FAILED`。
3. 检查当前时间未超过 `leaseExpireAt`。
4. 在 OutBox 同一磁盘写临时文件，flush 并关闭。
5. 持久化 `PREPARED` 写前记录并 flush。
6. 原子 rename 为后端指定的 `fileName`，禁止覆盖已有文件。
7. 持久化 `DELIVERED` 并 flush。
8. 回报 `OUTBOX_DROPPED`。

如果状态接口超时，只能重试同一个状态请求，不能再次写入 OutBox。

租约在正式 rename 前过期时，删除尚未投递的临时文件并告警，不要回报 `FAILED`。如果无法确认正式文件是否已经被单一窗口取走，应保留账本并等待人工处理，禁止自动重投。

## 6. 回报投递状态

### 6.1 请求

```http
POST /admin-api/declaration/agent/tasks/33/status
Content-Type: application/json
X-Agent-Key: sk-platform-replace-with-real-key
```

投递成功：

```json
{
  "instanceName": "PLATFORM-AGENT-01",
  "dispatchToken": "bb4635d4-0dc4-4ec8-8f33-8f9b7b650662",
  "status": "OUTBOX_DROPPED",
  "message": "已写入统一 OutBox，投递账本已落库"
}
```

明确未投递：

```json
{
  "instanceName": "PLATFORM-AGENT-01",
  "dispatchToken": "bb4635d4-0dc4-4ec8-8f33-8f9b7b650662",
  "status": "FAILED",
  "message": "统一 OutBox 目录不可写"
}
```

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| 路径 `taskId` | 是 | 正整数 | 必须来自 pull 响应。 |
| `instanceName` | 是 | 非空，最长 64 | 必须与 pull 时一致。 |
| `dispatchToken` | 是 | 非空，最长 64 | 必须是该任务本次分派令牌。 |
| `status` | 是 | `OUTBOX_DROPPED` 或 `FAILED` | 不接受其他状态。 |
| `message` | 否 | 最长 500 | 简短摘要，不得包含完整 XML 或 Key。 |

成功响应：

```json
{
  "code": 0,
  "msg": "",
  "data": true
}
```

后端仍会同时校验 `taskId`、`instanceName`、`dispatchToken` 和当前状态。重复回报同一结果是幂等的；使用旧令牌或错误实例名会返回状态冲突。

## 7. 扫描和关联回执

平台模式上传回执必须携带 `taskId`，因此前置机需要把 InBox 回执关联到此前拉取的任务：

1. 等待文件大小和最后修改时间连续两次扫描保持不变。
2. 按原始字节读取文件，并计算 SHA-256。
3. 使用禁用 DTD、外部实体和 XInclude 的安全 XML 解析器提取 `ClientSeqNo`。
4. 按 `clientSeqNo` 查询本地投递账本，必须恰好命中一条任务记录。
5. 唯一命中后取得对应的 `taskId`，上传原始字节的 Base64。
6. 未命中或出现多个候选时停止自动上传并告警，等待人工核查，禁止根据时间或租户进行猜测。

这里只允许读取 `ClientSeqNo` 用于任务关联。不得修改 XML，不得重新序列化，不得改变编码、换行、命名空间或元素顺序。上传的 Base64 必须来自最初读取的原始字节。

## 8. 上传回执

### 8.1 请求

```http
POST /admin-api/declaration/agent/receipts
Content-Type: application/json
X-Agent-Key: sk-platform-replace-with-real-key
```

```json
{
  "taskId": 33,
  "instanceName": "PLATFORM-AGENT-01",
  "tradeMode": "export",
  "fileName": "DecImportResponse_20260918124500.xml",
  "receivedAt": "2026-09-18 12:45:00",
  "receiptXmlBase64": "PERlY0ltcG9ydFJlc3BvbnNlPj4..."
}
```

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `taskId` | 是 | 正整数 | 必须是与回执 `ClientSeqNo` 对应的 pull 任务。 |
| `instanceName` | 是 | 非空，最长 64 | 当前平台实例名。 |
| `tradeMode` | 否 | `export`、`import`、`9610` | 建议使用任务账本中的值。 |
| `fileName` | 是 | 非空，最长 255 | InBox 原始文件名。 |
| `receivedAt` | 否 | 日期时间 | 文件被发现/接收的时间。 |
| `receiptXmlBase64` | 是 | Base64 文本最长 4 MiB | 解码后默认不得超过 3 MiB。 |

后端会执行双重校验：

- `taskId` 必须对应一个有效业务租户的 Agent 任务；
- XML 中的 `ClientSeqNo` 必须与任务保存的 `clientSeqNo` 完全一致。

请求体不要增加 `tenantId`。租户归属由后端从任务读取，前置机账本中的 `tenantId` 只用于交叉核对和告警。

### 8.2 响应

首次接收：

```json
{
  "code": 0,
  "msg": "",
  "data": {
    "matched": true,
    "taskId": 33,
    "customsStatus": "SUCCESS",
    "duplicate": false
  }
}
```

重复上传：

```json
{
  "code": 0,
  "msg": "",
  "data": {
    "matched": true,
    "taskId": 33,
    "customsStatus": "SUCCESS",
    "duplicate": true
  }
}
```

| 字段 | 处理规则 |
|---|---|
| `matched = true` | 回执已关联后端任务，可记为 `ACKED_MATCHED`。 |
| `duplicate = true` | 后端已接收相同内容，视为成功，不再上传。 |
| `customsStatus = SUCCESS` | 暂存回执 `ResponseCode = 0`。 |
| `customsStatus = FAILED` | 暂存回执 `ResponseCode != 0`。 |
| `matched = false` | 停止自动重传并告警，等待人工核查。 |

后端幂等键为 `tenantId + ClientSeqNo + XML SHA-256`。本地回执账本建议以 `taskId + xmlSha256` 唯一，至少记录 `tenantId`、`clientSeqNo`、文件路径、文件名、上传状态、最后错误和重试时间。

## 10. 状态机和恢复原则

```text
READY
  -> DISPATCHED
      -> RECEIPT_PENDING -> SUCCESS / FAILED
      -> UPLOAD_FAILED
      -> DELIVERY_UNKNOWN
```

| 后端状态变化 | 触发条件 |
|---|---|
| `READY -> DISPATCHED` | pull 原子抢占成功。 |
| `DISPATCHED -> RECEIPT_PENDING` | 回报 `OUTBOX_DROPPED`。 |
| `DISPATCHED -> UPLOAD_FAILED` | 文件进入 OutBox 前明确失败并回报 `FAILED`。 |
| `DISPATCHED -> DELIVERY_UNKNOWN` | 租约过期且后端无法判断是否已经投递。 |
| 非终态 -> `SUCCESS/FAILED` | 后端收到并匹配暂存回执。 |

`DELIVERY_UNKNOWN` 不会自动重新投递。平台前置机不得自行重写 OutBox，必须保留账本等待后端管理员人工裁决。

## 11. 重试与本地状态

### 11.1 状态接口

- 超时、连接断开或响应未知：重试相同 `taskId + dispatchToken + status`。
- 严禁因为状态接口失败而再次写 OutBox。
- `1050000202` 或 `1050000203`：停止自动重试该状态回报并告警。

### 11.2 回执接口

建议本地回执状态：

| 状态 | 含义 | 后续动作 |
|---|---|---|
| `PENDING` | 新发现，尚未获得明确响应 | 上传。 |
| `RETRY_PENDING` | 网络、超时或后端临时异常 | 指数退避后重试。 |
| `ACKED_MATCHED` | 后端已接收并匹配 | 后续扫描直接跳过。 |
| `ACKED_UNMATCHED` | 后端明确返回未匹配 | 停止重传并告警。 |
| `PERMANENT_REJECTED` | XML/Base64 非法、过大或任务身份不匹配 | 停止重传并告警。 |

InBox 原文件不得因上传成功或失败被前置机移动、重命名或删除。历史文件由现场按约定清理。

## 12. 错误码处理

| HTTP | `code` | 含义 | 前置机处理 |
|---|---:|---|---|
| 503 | `1050000200` | 前置机通道关闭 | 停止拉取，至少 60 秒低频探测并告警。 |
| 401 | `1050000201` | 平台 Key 无效 | 停止高频请求并告警，等待更新 Key。 |
| 通常 200 | `1050000202` | 任务不存在或不在有效业务租户范围 | 不重试原请求，核查账本并告警。 |
| 通常 200 | `1050000203` | 任务状态、实例名或分派令牌冲突 | 不重写 OutBox，核查账本并告警。 |
| 通常 200 | `1050000204` | 回执 XML/Base64 无效或缺少 `ClientSeqNo` | 记为永久拒绝。 |
| 通常 200 | `1050000205` | 回执解码后超过大小限制 | 记为永久拒绝。 |
| 通常 200 | `1050000208` | 后端未正确配置平台 heartbeat 归属租户 | 低频重试并通知后端运维。 |
| 通常 200 | `1050000209` | 回执缺少 `taskId` 或 `taskId` 与 `ClientSeqNo` 不匹配 | 停止重试当前组合，核查本地关联。 |
| 通常 200 | `400` | 请求字段或格式校验失败 | 修复请求后再发送。 |
| 5xx | `500` 或其他 | 后端临时异常 | 指数退避重试。 |

推荐退避：1 秒起步，按 2 倍增长，最大 60 秒，加入 0～20% 随机抖动。鉴权失败、通道关闭和 heartbeat 配置错误使用至少 60 秒的低频探测。

## 13. 安全要求

- 平台 Key 具有跨租户能力，只能存放于受限配置或操作系统凭据存储中。
- 日志、异常、监控、截图和工单不得输出完整 Key，最多显示末 4 位。
- 不得记录完整 `decXmlBase64`、`receiptXmlBase64` 或解码后的 XML。
- 日志只记录 `taskId`、`tenantId`、`clientSeqNo`、文件名、SHA-256、状态和错误摘要。
- 生产环境必须校验证书链和主机名，不得关闭 TLS 校验。
- XML 解析必须禁用 DTD、外部实体和 XInclude，防止 XXE。
- 不得根据请求或账本中的 `tenantId` 修改 DEC/回执 XML。

## 14. 联调验收清单

- [ ] 平台 Key 可以调用四个接口，错误 Key 返回 401。
- [ ] 一次 pull 可以返回不同 `tenantId` 的任务。
- [ ] pull 空任务返回正常空数组。
- [ ] DEC Base64 解码后的 SHA-256 与 `xmlSha256` 一致。
- [ ] 所有 `tradeMode` 均写入统一 OutBox。
- [ ] 同一任务只写一次 OutBox，状态超时不会重复写文件。
- [ ] status 使用原始 `taskId`、`instanceName` 和 `dispatchToken`。
- [ ] 本地账本完整保存 `taskId + tenantId + clientSeqNo + xmlSha256`。
- [ ] InBox 回执能够通过 `ClientSeqNo` 唯一关联到 `taskId`。
- [ ] 回执上传包含 `taskId`，上传字节与 InBox 原文件完全一致。
- [ ] 故意传错 `taskId` 时收到 `1050000209`，不会串租户落库。
- [ ] 重复上传相同回执返回 `duplicate = true`，前置机停止重传。
- [ ] heartbeat 能获得服务器时间，连续离线能产生本地告警。
- [ ] 进程重启后可从投递账本和回执账本恢复。
- [ ] 日志中不存在完整 Key、XML 或 Base64。

## 15. 双方职责边界

| 后端负责 | 平台前置机负责 |
|---|---|
| 平台 Key 鉴权和有效业务租户筛选 | 安全保存并使用平台 Key |
| 跨租户任务查询与原子抢占 | 拉取任务并持久化真实租户信息 |
| 生成 DEC、文件名、流水号、SHA-256 和分派令牌 | 校验、写前日志、原子投递和状态回报 |
| 校验 `taskId + ClientSeqNo` 并按真实租户落库 | 从回执安全读取 `ClientSeqNo` 并关联本地任务 |
| 回执解析、幂等、状态更新和历史记录 | 原样上传回执字节并维护重试账本 |
